# Patch

## diff 
- 두 파일이나 디렉토리 간의 텍스트 차이를 줄 단위로 비교하여 출력함
```
diff [옵션] [원본 파일/디렉토리] [수정된 파일/디렉토리]
```
- 옵션
  - `-u`(Unified format)
    - 패치 파일의 표준이 되는 형태로, 변경된 부분의 위아래 문맥(Context) 3줄을 함께 보여줌
    - patch 명령어가 파일의 어느 위치를 수정해야 하는지 정확히 파악할 수 있게 해주는 가장 필수적인 옵션
  - `-r`(Recursive)
    - 디렉토리를 비교할 때 하위 디렉토리와 그 안의 파일들까지 모두 재귀적으로 탐색하며 비교함
  - `-N`(New file)
    - 원본에는 없고 수정된 디렉토리에만 새로 추가된 파일이 있다면, 이를 빈 파일과 비교하여 패치 내역에 '새 파일 생성' 과정을 포함시킴
  - `-a`(Text)
    - 바이너리 의심 파일도 모두 강제로 텍스트로 간주하여 비교
- 예시 : `diff -u vuln.c vuln_patched.c > fix_bof.patch`
  - 두 파일의 차이점과 문맥이 기록된 fix_bof.patch 파일이 생성됨 
- 패치 파일 정보
  ```
  --- old.c
  +++ new.c
  @@ -1,5 +1,5 @@
   int main() {
  -    printf("Hello");
  +    printf("Hello World");
       return 0;
   }
  ```
  - `--- old.c` : 원본 파일
  - `+++ new.c` : 수정된 파일
  - `@@ -1,5 +1,5 @@` : 변경된 위치 정보
  - `-` : 원본에서 삭제된 줄
  - `+` : 새로 추가된 줄
- 두 디렉토리 전체를 비교해서 패치 생성 : `diff -ruN project_original project_modified > project.patch`
  - 프로젝트 전체 차이를 project.patch에 저장 

## patch
- diff 로 만든 패치 파일을 읽어들여, 명시된 변경 사항을 원본 파일에 자동으로 적용함
```
patch [옵션] < [패치 파일]
```
- 옵션
  - `p[숫자]` (Strip) : 패치 파일 내부에 기록된 파일의 경로에서 몇 개의 디렉토리 계층을 무시(잘라내기)할 것인지 지정
    - `-p0` : 패치 파일에 적힌 경로를 자르지 않고 그대로 따라감
    - `-p1` : 최상위 디렉토리 하나를 무시함 (오픈소스 프로젝트에서 패치를 배포할 때 가장 많이 사용하는 방식)
    - 예시  
      패치 파일 내부 파일 경로 
      ```
      --- old_project/src/main.c
      +++ new_project/src/main.c
      ```
      - 현재 내가 이미 `project_original` 안에 들어와있으면 실제 파일 경로는 `src/main.c`여야 함
      - 앞의 디렉토리 이름 하나를 잘라내야 하므로 `-p1` 옵션을 지정해야 함 (`patch -p1 < ../fix.patch`)
  - `--dry-run` : 실제 파일을 수정하지 않고, 패치가 충돌없이 성공적으로 적용될 수 있는지 시뮬레이션만 해보는 안전장치 옵션
  - `-R` (Reverse) : 이미 적용한 패치를 원래 상태로 되돌림 (롤백 가능)
- 패치 파일을 프로젝트에 적용하려면 보통 원본 프로젝트 디렉토리로 들어간 뒤 실행함
  ```
  cd project_original
  patch -p1 < ../fix.patch
  ```
- 예시 : `patch < fix_bof.patch`
  - 현재 디렉토리에 있는 vuln.c 파일이 패치 내용에 맞게 자동으로 수정됨

## 예시
- 원본 프로젝트 : `myproj/`
- 수정본 프로젝트 : `myproj_fixed/`
1. 패치 파일 만들기 : `diff -ruN myproj myproj_fixed > myfix.patch`  
2. 패치 적용하기  
   ```
   cd myproj
   patch -p1 < ../myfix.patch
   ```
3. 적용 잘 됐는지 확인 : `diff -ruN ../myproj_fixed .` (아무것도 출력되지 않으면 두 디렉토리가 같다는 뜻)
- 실제로 적용하지 않고 되는지만 보고 싶으면 `patch --dry-run -p1 < ../myfix.patch`
  - 성공하면 `checking file src/main.c` 이런 식으로 결과 나옴
4. 패치 적용 취소하기 : `patch -R -p1 < ../myfix.patch`
